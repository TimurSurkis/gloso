# Документация backend Gloso

Версия проекта документов: 0.2. Обновлено: 26 ноября 2026 г.

## Статусы и порядок работы

Это document-first проектирование, **не описание уже работающей системы**.

- **Согласовано** — решения владельца D-001–D-075 из [реестра решений](concepts/decision-backend.md). D-003 заменено; D-019 обновлено (любой валидный E.164 с дефолтом +48); D-020 в части провайдеров заменено D-069 (Twilio вместо Zadarma/SMSAPI); D-004/D-005 относятся только к будущему расширению.
- **Проект** — техническое предложение в спецификациях. Схемы таблиц, маршруты, алгоритмы и инженерные значения по умолчанию ещё подлежат проверке согласованности и ревью.
- **Блокер пилота** — возможность внешнего сервиса или эксплуатационная гарантия, которую нельзя считать подтверждённой до проверки. См. [трекер проверок](trackers/track-backend-validation.md).

При конфликте техническое предложение исправляется под согласованное требование; новое продуктовое решение не вводится молча. Существенные вопросы владельцу задаются по одному. Промпты вне текущей работы.

Сначала завершаются и проверяются технические документы, **затем на их основе обновляются регламент и политика приватности**. Сейчас юридические HTML-файлы не изменяются; они ещё содержат прежние упоминания Zadarma/SMSAPI и будут обновлены после финализации технической модели. До живого запуска система и юридические условия должны быть согласованы.

## История и источники

- [Реестр решений](concepts/decision-backend.md) сохраняет договорённости и их изменения.
- [Трекер интервью](trackers/track-backend-discovery.md) содержит историю вопросов; незакрытые чекбоксы не равны автоматически новым вопросам владельцу.
- `spec-legacy-architecture.md`, `spec-legacy-architecture-scheme.md`, `spec-legacy-database.md`, `spec-legacy-project.md` в корне `docs/` — **исторические материалы**, не актуальная спецификация нового backend. Их содержание сохранено, обновлены имена и ссылки; они могут противоречить новому проекту.

В документации нет ключей, токенов, реальных телефонов звонящих или содержимого их обращений. Публичные документации провайдеров и реальные контракты ещё не проверены в рамках этого проекта документов; предполагаемые endpoints Gloso не являются endpoints провайдеров.

## Правила именования файлов

Все Markdown-файлы в `docs/` именуются в `kebab-case` с префиксом по содержанию:

| Префикс     | Назначение                                       |
| ----------- | ------------------------------------------------ |
| `index-`    | Оглавление и навигация                           |
| `concept-`  | Концепция и обзор                                |
| `decision-` | Реестр согласованных решений                     |
| `spec-`     | Спецификация, в том числе явно помеченный проект |
| `track-`    | Трекер состояния, проверок или интервью          |
| `plan-`     | План работ и этапов                              |

Для исторических спецификаций используется `spec-legacy-...`. Для нового типа документа выбирается соответствующий смысловой префикс. При переименовании обновляются относительные ссылки и упоминания путей; папка не заменяет префикс имени. Юридические HTML-файлы в корне проекта этим правилом не переименовываются.
