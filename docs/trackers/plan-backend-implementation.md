# План реализации и критерии приёмки

Статус: **проект плана v0.1**, не отчёт о выполненной работе. Основание D-065: сначала документация, затем локальный backend, реальные интеграции и проверка до пилота. D-069 заменяет Zadarma/SMSAPI на Twilio.

## Этапы

### 0. Завершить document-first проект

- [ ] Ревью спецификаций и устранение противоречий; отдельное подтверждение ещё не согласованных продуктовых выборов.
- [ ] Проверка реальных публичных контрактов провайдеров и список обязательных экспериментальных проверок.
- [ ] Зафиксировать версии runtime/зависимостей, границы модулей, поля таблиц, собственные API, условия восстановления и технические defaults.
- [ ] Зафиксировать явные блокеры production в [трекере](track-backend-validation.md); не подменять отсутствующие контракты фиктивными.

### 1. Локальное ядро

- [ ] Структура модульного монолита; конфигурация, отдельные полномочия, Zod, безопасные ошибки/логи.
- [ ] PostgreSQL/Drizzle, явные миграции, тестовая БД и повторяемые фиктивные данные без реальных обращений.
- [ ] Admin API: настройки, каталог, расписание, ручная активация, пауза/возобновление, технические статусы.
- [ ] Домен времени/праздников/слотов и подписанная ссылка на слот.
- [ ] Допуск/учёт и журнал внешних операций, audit allowlist/шифрование/ретенция.

### 2. Mock-интеграции и отказоустойчивость

- [ ] Calendar/SMS/events adapters с явным тестовым режимом и управляемыми ошибками.
- [ ] Сценарии Calendar/Relay, единственный результат разговора, отдельный результат SMS.
- [ ] Межпроцессная сериализация, неизвестный исход и безопасная ручная сверка.
- [ ] Повторы SMS только в памяти, технические Telegram-сигналы без персонального содержимого.
- [ ] Тесты с реальным PostgreSQL, двумя процессами backend и внешним тестовым провайдером, переживающим рестарт backend.

### 3. Настоящие сервисы

- [ ] Реальный тестовый Calendar и Service Account; не использовать личные обращения в отладке.
- [ ] Реальные доверенные tools/events ElevenLabs без аудио/транскрипций в backend.
- [ ] Twilio Programmable Messaging: проверка отправки, ошибок и ограничений с выделенным тестовым получателем и польским отправителем.
- [ ] Twilio/ElevenLabs: допуск до AI, резервные маршруты, привязки и максимальная длительность; проверить, что нативная интеграция не обходит backend.
- [ ] Telegram и мониторинг; ограниченные безопасные технические сообщения.

Доступные реальные сервисы можно испытывать раньше по мере готовности. Все боевые расходы и создание платных ресурсов требуют явного согласования.

### 4. До живого пилота

- [ ] Northflank + Neon в ЕЭЗ, миграции/секреты/health/readiness/фоновые задачи.
- [ ] Проверенное удаление и backup/restore, отсутствие утечек инфраструктурными логами.
- [ ] Обновлённые на основе технических спецификаций регламент и политика приватности.
- [ ] Сквозная приёмка реальными тестовыми звонками, затем ручная активация 3–5 согласованных автосервисов.

## Матрица обязательных сценариев

| ID | Сценарий | Ожидаемый результат |
| --- | --- | --- |
| A-01 | Создание tenant/повтор конфигурации | Пилот не начинается сам, чужие привязки не перезаписываются |
| A-02 | Активация/повтор активации | Один старт, 14 календарных дней Europe/Warsaw, без сброса расхода |
| A-03 | Пауза/возобновление | Только новые AI-звонки; срок/минуты неизменны, оконченный пилот не оживает |
| A-04 | Последний доступный допуск, два процесса | Не более одного разговора tenant, без двойного решения/резерва |
| A-05 | Два разных tenant | Независимость допусков, календарей, получателей и восстановления |
| A-06 | Конец срока/минут во время разговора | Текущий не обрывается по балансу, следующий старт запрещён |
| A-07 | Backend/БД не отвечает | Нет нового AI, резервный маршрут телефонии реально работает |
| A-08 | Максимум 180 секунд/потерянный end | Ограничение применено провайдером, локальный lease не выдаёт ложный конец |
| A-09 | 0/1/60/61 секунда и повтор события | 0/1/1/2 минуты, однократно; без AI нет списания |
| A-10 | Поздний/replay/старый call event | Не создаёт новый расход после удаления ключей; требует безопасного разбора |
| A-11 | Праздник/явное открытие/перерыв | Приоритеты расписания, полный визит не пересекает запрет |
| A-12 | Минимум 60 минут, горизонт, шаг, буфер | Все условия одновременно, длительность услуги не округляется |
| A-13 | DST, прошлое/несуществующее/двусмысленное время | Нет случайного или неоднозначного визита |
| A-14 | Нет услуги/комплекса/слотов | Relay разрешён, бронирование не обещается |
| A-15 | Успешная запись/повтор tool call | Один Google event, один логический SMS, прежний результат |
| A-16 | Конфликт до создания, затем другой слот | Нет первой записи, допустима одна успешная новая попытка |
| A-17 | Падение до/после Google insert и до commit | Неизвестный исход сверяется по прежнему ID, дубля нет |
| A-18 | `404` при ещё выполняющемся insert, `409`, `5xx` | Gate не освобождается по ложному доказательству отсутствия |
| A-19 | Истёкший lease/старый владелец/новый процесс | Нет нового бронирования поверх неизвестного внешнего действия |
| A-20 | Calendar на сверке, новый звонок | Новая Relay-заявка допустима, исходная неизвестная не дублируется |
| A-21 | Создание успешно, SMS отказал | Визит сохранён, аудит «запись создана», отдельный сигнал администратору |
| A-22 | Временный/постоянный/неизвестный SMS-исход | Только допустимые повторы в памяти, без слепого повтора неизвестного |
| A-23 | Рестарт во время Relay/SMS | Нет восстановления текста из БД, нет ложной гарантии доставки |
| A-24 | Другой контакт/скрытый Caller ID | Явный польский контакт принят без OTP; нет полномочий на старые визиты |
| A-25 | Подмена tenant/call/service/slot/подписи | Отказ до внешнего действия, чужие данные не раскрываются |
| A-26 | Истёкший токен завершённой/новой операции | Только безопасный повтор старого результата, не новое создание |
| A-27 | Без операции/неизвестный исход | Результат аудита отсутствует, не четвёртый статус и не ложная ошибка |
| A-28 | Аудит: время, длительность, сохранение | Часовой интервал, целые списанные минуты, ни секунды/PII/скрытой точной метки |
| A-29 | Срок 7 дней, неизвестная операция | Ссылки удалены, минимальный запрет остаётся до безопасной проверки |
| A-30 | Срок аудита/простой/backup restore | Нет чтения истёкшего, нет возвращения после восстановления; физическая политика проверена |
| A-31 | Telegram/логи/ошибки SDK | Нет текста/контактов/секретов, один логический сигнал на переход |
| A-32 | Live с тестовыми headers/adapters | Отказ запуска/конфигурации, не фиктивный production-успех |
| A-33 | Визит после конца пилота | Во время активного пилота создание разрешено в пределах горизонта; окончание пилота событие не отменяет |
| A-34 | Twilio → ElevenLabs и допуск | Проверка допуска выполняется до старта AI; нативная интеграция, обходящая backend, не включается |
| A-35 | Twilio: номер, отправитель, регион | Польский номер и отправитель SMS подтверждены; регион/DPA отражены в политике; нет ложного production-успеха |

Матрица задаёт план тестов, а не заявляет, что эти сценарии уже проверены. Для сетевых гарантий недостаточно unit-тестов mock-адаптера: нужны реальные контрактные/сквозные проверки.
